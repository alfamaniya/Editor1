# برنامه تفکیک کاتالوگ تکمیل خودکار به سه فایل

## هدف

تفکیک فایل داده یکپارچه اولیه به سه فایل مستقل HTML، CSS و JavaScript، بدون تغییر معنایی رکوردها و بدون اتصال زودهنگام فایل‌های جدید به runtime.

## وضعیت کلی

- [x] مرحله ۱ — ایجاد سه فایل داده و انتقال رکوردها (فایل‌ها ایجاد و JSON/تعداد/زبان رکوردها بررسی اولیه شد؛ آزمون‌های جامع در مرحله ۲ و ۳ است)
- [x] مرحله ۲ — اصلاح آزمون‌ها برای خواندن و اعتبارسنجی سه فایل
- [x] مرحله ۳ — اجرای آزمون‌ها و بررسی نتیجه GitHub Actions (Run #151: ۴۳ موفق، صفر ناموفق)
- [x] مرحله ۴ — ممیزی ارجاع‌ها و حذف فایل یکپارچه قدیمی؛ هیچ مصرف‌کننده اجرایی به آن وابسته نبود.
- [ ] مرحله ۵ — نهایی‌سازی مستندات و بازبینی ساختار

## قرارداد فایل‌های جدید

| زبان | مسیر | تعداد مورد انتظار |
|---|---|---:|
| HTML | `alfacode/data/completions.html.json` | ۶۰ |
| CSS | `alfacode/data/completions.css.json` | ۱۷۴ |
| JavaScript | `alfacode/data/completions.javascript.json` | ۱۱۴ |

هر فایل envelope مستقل و یکسان خواهد داشت:

```json
{
  "schemaVersion": 1,
  "catalogVersion": 1,
  "records": []
}
```

فیلد `language` در تمام رکوردها حفظ می‌شود. همه شناسه‌ها، ترتیب رکوردها، فیلدها و مقادیر باید بدون تغییر منتقل شوند.

## مراحل اجرایی خرد

### مرحله ۱ — ایجاد فایل‌های داده

- [x] ۱-۱. دریافت آخرین نسخه فایل مرجع از شاخه `main`.
- [x] ۱-۲. تفکیک رکوردها فقط بر اساس مقدار دقیق `language`.
- [x] ۱-۳. ایجاد سه فایل JSON با envelope یکسان.
- [x] ۱-۴. کنترل تعداد رکوردها و صحت JSON هر فایل.
- [ ] ۱-۵. نگه‌داشتن فایل یکپارچه قدیمی؛ در این مرحله هیچ فایلی حذف نمی‌شود.

**معیار پذیرش:** سه فایل معتبر با تعدادهای ۶۰، ۱۷۴ و ۱۱۴ ایجاد شده باشند و مجموع رکوردها ۳۴۸ باشد؛ هیچ رکورد یا فیلدی تغییر نکرده باشد.

### مرحله ۲ — اصلاح آزمون‌های داده

- [x] ۲-۱. دریافت آخرین نسخه آزمون‌های فعلی و بررسی تمام ارجاع‌ها به فایل قدیمی.

- [x] ۲-۳. حفظ تمام آزمون‌های موجود و افزودن کنترل زبان هر فایل.
- [x] ۲-۴. حفظ کنترل یکتایی شناسه‌ها و کلیدهای معنایی در مجموعه ادغام‌شده.
- [x] ۲-۵. کنترل تعداد کل و تعداد هر زبان و اعتبارسنجی schema هر فایل.

**معیار پذیرش:** همه ۱۷ آزمون فعلی فایل داده حفظ شده‌اند؛ loader سه فایل را می‌خواند، envelope و نسخه‌ها، زبان هر فایل، تعداد رکوردها، schema و یکتایی شناسه‌ها/کلیدهای معنایی در مجموعه ادغام‌شده را کنترل می‌کند. اجرای واقعی ۴۳ آزمون در مرحله ۳ با موفقیت تأیید شد.

## محدودیت دامنه

- این تغییر صرفاً تفکیک داده و آزمون‌هاست؛ اتصال کاتالوگ به موتورهای runtime در این برنامه انجام نمی‌شود.
- فایل‌های جدید تا پیش از عبور از آزمون‌ها جایگزین قطعی فایل قدیمی محسوب نمی‌شوند.
- تغییر در schema، نسخه کاتالوگ، منطق پیشنهادها یا محتوای رکوردها خارج از دامنه این کار است.
