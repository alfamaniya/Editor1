# قوانین و ساختار پروژه Editor1

## تاریخچه توسعه AlfaCode

موتور AlfaCode به‌صورت ماژولار ساخته و به محیط Editor1 متصل شد. در این مسیر، مدل سند و وضعیت ویرایشگر، انتخاب و مکان‌نما، تراکنش‌های اتمی و تاریخچه Undo/Redo توسعه یافتند؛ سپس ورودی صفحه‌کلید و کلیپ‌بورد، رندر خطوط، مدیریت زبان و تحلیل پایه HTML/CSS/JavaScript، رنگ‌بندی نحوی، شماره خطوط، تطبیق پرانتزها و تم‌های روشن و تاریک اضافه شدند. مجموعه آزمون خودکار پایه و گردش‌کار CI نیز ایجاد شد.

در مرحله یکپارچه‌سازی، موتور به رابط Editor1 و Live Preview متصل شد؛ همگام‌سازی مکان‌نما و انتخاب متن و اسکرول مشترک gutter و ویرایشگر اصلاح شد. در بررسی آفلاین، مسیرهای محلی منابع و شیوه اجرای پروژه با سرور محلی مستند شدند. تاریخچه تفصیلی APIها و اجزای AlfaCode در README اختصاصی آن نگهداری می‌شود.

## نقشه مسیر — پیشنهاد و تکمیل خودکار تگ‌های HTML

این نقشه مسیر، محدوده و ترتیب توسعه قابلیت پیشنهاد تگ‌ها را مشخص می‌کند. تا پیش از تأیید نقشه و روشن‌شدن رفتار «پیشنهاد بعد از پیشنهاد»، هیچ‌یک از مراحل اجرایی این قابلیت آغاز نمی‌شود.

**ساختار ماژول رابط:** `core/tag-suggestions/` با سه فایل `tag-suggestions.html`، `tag-suggestions.css` و `tag-suggestions.js`. منطق عمومی و داده‌های زبان در لایه AlfaCode باقی می‌مانند و رابط فقط مسئول نمایش و تعامل خواهد بود.

**قواعد اجرایی:** هر مرحله پس از تکمیل آزمون و بازبینی، وضعیتش در همین جدول به‌روزرسانی می‌شود. هر تغییر ساختاری یا عملکردی باید هم‌زمان در README اصلی و README اختصاصی AlfaCode منعکس شود. نسخه آفلاین نیز باید از همان سورس اصلی ساخته شود و منطق جداگانه یا قدیمی نداشته باشد.

## قوانین اصلی پروژه

1. فایل‌های ریشه شامل `index.html`، `style.css` و `script.js` هسته مرکزی پروژه هستند.
2. هر بخش مستقل باید پوشه اختصاصی با نام مرتبط در مسیر `core/` داشته باشد.
3. هر بخش باید دقیقاً سه فایل اصلی داشته باشد: HTML، CSS و JavaScript.
4. کدهای اختصاصی هر بخش باید فقط در پوشه همان بخش قرار بگیرند.
5. فایل‌های ریشه مسئول چیدمان کلی و اتصال بخش‌ها هستند؛ منطق اختصاصی بخش‌ها نباید به فایل‌های ریشه منتقل شود.
6. زبان README فارسی است؛ اما تمام متن‌های رابط کاربری، نام‌گذاری‌ها، شناسه‌ها و توضیحات داخل کد باید انگلیسی باشند.
7. در هر تغییر ساختاری یا عملکردی، این فایل و README اختصاصی AlfaCode باید متناسب با وضعیت واقعی پروژه به‌روزرسانی شوند.
8. ساختار بخش‌ها باید مستقل و قابل توسعه باقی بماند.
9. قابلیت جدید فقط با درخواست صریح مدیر پروژه پیاده‌سازی می‌شود.

## معرفی پروژه

Editor1 یک پروژه ماژولار برای توسعه محیط ویرایش کد است. در ساختار فعلی، صفحه اصلی شامل دو بخش ظاهری Editor و Live Preview است.

پوشه `alfacode/` محل توسعه موتور ویرایشگر کد اختصاصی AlfaCode است؛ موتوری مستقل و ماژولار با الهام از معماری و قابلیت‌های ویرایشگرهایی مانند Monaco و CodeMirror.

نسخه اولیه AlfaCode برای شناخت و پشتیبانی از HTML، CSS و JavaScript طراحی می‌شود. معماری باید امکان افزودن زبان‌های دیگر را بدون بازنویسی هسته فراهم کند. توسعه با اولویت اجرای محلی و آفلاین انجام خواهد شد.

## مسئولیت بخش‌های اصلی AlfaCode

- `src/core/`: مدیریت وضعیت ویرایشگر، سند، انتخاب متن، تراکنش‌ها و تاریخچه.
- `src/rendering/`: نمایش محیط ویرایش، خطوط و مکان‌نما.
- `src/input/`: دریافت ورودی صفحه‌کلید و مدیریت کلیپ‌بورد.
- `src/language/`: مدیریت زبان‌ها، توکن‌سازی و هماهنگی تحلیلگرها.
- `src/language/html/`: قواعد و تحلیل ساختار HTML.
- `src/language/css/`: قواعد و تحلیل ساختار CSS.
- `src/language/javascript/`: قواعد و تحلیل ساختار JavaScript.
- `src/features/`: امکانات مستقل مانند شماره خطوط، رنگ‌بندی نحوی و تطبیق پرانتزها.
- `src/themes/`: مدیریت تم‌های روشن و تاریک.
- `src/utils/`: ابزارهای عمومی مشترک.
- `tests/`: محل آزمون‌های خودکار.
- `examples/`: نمونه‌های استفاده از موتور.

## وضعیت پیاده‌سازی

AlfaCode به محیط Editor1 متصل است و قابلیت‌های پایه ویرایش، رنگ‌بندی نحوی، شماره خطوط، تطبیق پرانتزها و انتقال تغییرات به Live Preview را فراهم می‌کند. فایل‌های موردنیاز پروژه به‌صورت محلی نگهداری می‌شوند و اجرای آفلاین از طریق سرور محلی امکان‌پذیر است.

## اجرای پروژه

برای اجرای نسخه یکپارچه و آفلاین، در ریشه مخزن یک سرور محلی اجرا کنید؛ برای نمونه در ویندوز با Python:

```powershell
py -m http.server 8000
```

سپس نشانی `http://localhost:8000` را در مرورگر باز کنید. این سرور فقط فایل‌های همین پوشه را روی رایانه ارائه می‌کند و به اینترنت نیاز ندارد. استفاده از سرور محلی ضروری است؛ بارگذاری مستقیم `index.html` با نشانی `file://` ممکن است به‌دلیل محدودیت امنیتی مرورگر در بارگذاری ES Modules شکست بخورد. پس از بازشدن برنامه می‌توان اتصال اینترنت را قطع کرد؛ همه فایل‌های اجرایی و stylesheetهای پروژه محلی هستند.


## رنگ‌بندی نحوی (Syntax Highlighting)

ماژول رنگ‌بندی نحوی در مسیر `alfacode/src/features/syntax-highlighting/highlighter.js` پیاده‌سازی می‌کند. این ماژول متن را تحلیل نمی‌کند؛ توکن‌های تولیدشده توسط زبان فعال را دریافت می‌کند و آن‌ها را به گره‌های DOM دارای کلاس‌های معنایی تبدیل می‌کند.

- کلاس `SyntaxHighlighter` با متد `render(sourceText, tokens, ownerDocument)` یک `DocumentFragment` می‌سازد.
- متد `renderInto(container, sourceText, tokens)` محتوای نمایشی یک container را با نسخه رنگ‌بندی‌شده جایگزین می‌کند.
- تابع `highlightTokens(sourceText, tokens, ownerDocument, options)` برای استفاده مستقیم در دسترس است.
- نگاشت مشترک انواع توکن HTML، CSS و JavaScript به گروه‌های معنایی مانند `keyword`، `tag`، `attribute`، `string`، `number`، `comment`، `operator` و `punctuation` انجام می‌شود.
- کلاس‌های تولیدشده با پیشوند پیش‌فرض `alfacode-token` ساخته می‌شوند؛ برای نمونه `alfacode-token--keyword` و `alfacode-token--comment`. نوع دقیق توکن نیز در کلاس و ویژگی `data-token-type` حفظ می‌شود.
- فاصله‌ها و بخش‌های بدون توکن با text node نگهداری می‌شوند تا متن منبع بدون حذف یا جابه‌جایی باقی بماند.
- محتوای کد فقط با `createTextNode` و `textContent` وارد DOM می‌شود؛ از `innerHTML` استفاده نمی‌شود.
- ورودی CRLF و CR به LF نرمال می‌شود و موقعیت‌ها مطابق قرارداد UTF-16، صفرمبنا و با انتهای غیرشامل هستند. توکن‌های نامعتبر، خارج از محدوده، نامرتب یا هم‌پوشان رد می‌شوند.
- این ماژول کلاس‌های معنایی را تولید می‌کند؛ تعریف رنگ‌های واقعی و قواعد CSS تم‌ها در مدیریت تم‌ها انجام شده است. اتصال خودکار highlighter به چرخه ویرایش و آزمون مرورگر نیز در مراحل یکپارچه‌سازی و آزمایش بررسی می‌شود.
- بازبینی ایستا انجام شده است؛ آزمون کامل مرورگر هنوز اجرا نشده است.


## شماره خطوط و تطبیق پرانتزها

ماژول شماره خطوط و تطبیق پرانتزها دو قابلیت مستقل در مسیر `alfacode/src/features/` اضافه می‌کند. این قابلیت‌ها در یکپارچه‌سازی با رابط Editor1 به چرخه نمایش EditorView متصل شده‌اند.

### شماره خطوط

فایل `src/features/line-numbers/line-numbers.js` شامل کلاس `LineNumbers` است:

- `new LineNumbers(options)` برای تنظیم کلاس‌های CSS و برچسب دسترس‌پذیری.
- `render(documentModel, ownerDocument, activeLine)` یک عنصر gutter شامل شماره‌های ۱ تا تعداد خطوط سند می‌سازد.
- `renderInto(container, documentModel, activeLine)` محتوای container را با gutter تولیدشده جایگزین می‌کند.
- تعداد خطوط مستقیماً از `Document.getLineCount()` خوانده می‌شود؛ سند خالی نیز یک خط دارد.
- شماره‌ها با `data-line-number` مشخص می‌شوند و خط فعال اختیاری با کلاس و ویژگی داده‌ای جداگانه علامت‌گذاری می‌شود.
- ساختار و کلاس‌های معنایی تولید می‌شوند؛ اندازه، فاصله و رنگ در CSS تم‌ها تعریف خواهند شد.

### تطبیق پرانتزها

فایل `src/features/bracket-matching/bracket-matcher.js` شامل کلاس `BracketMatcher` است:

- `isBracket(character)` بررسی می‌کند که کاراکتر یکی از `()`، `[]` یا `{}` باشد.
- `findAll(sourceText, tokens)` تمام جفت‌های معتبر را با موقعیت باز و بسته برمی‌گرداند.
- `findMatch(sourceText, cursorOffset, tokens)` جفت مرتبط با کاراکتر زیر مکان‌نما یا کاراکتر بلافاصله پیش از آن را پیدا می‌کند؛ در صورت نبود جفت معتبر `null` برمی‌گرداند.
- الگوریتم از پشته برای مدیریت جفت‌های تو در تو استفاده می‌کند.
- در صورت ارائه توکن‌ها، محدوده رشته‌ها، templateها، regexها، کامنت‌ها، متن HTML، مقدار ویژگی‌ها و doctype از جست‌وجو کنار گذاشته می‌شوند تا براکت‌های داخل آن‌ها به‌عنوان ساختار کد تفسیر نشوند.
- توکن‌های ورودی باید مرتب، معتبر و بدون هم‌پوشانی باشند. موقعیت‌ها صفرمبنا و بر اساس UTF-16 هستند.
- فقط جفت‌های کامل و درست‌تودرتو گزارش می‌شوند؛ علامت‌گذاری بصری جفت‌ها و اتصال به مکان‌نما در یکپارچه‌سازی با رابط Editor1 انجام شده است.

### وضعیت بررسی

بازبینی ایستا و تطبیق APIها با مدل سند و قرارداد توکن‌ها انجام شده است. آزمون‌های پایه موتور در آزمون‌های پایه موفق بوده‌اند و اتصال قابلیت‌ها به DOM در یکپارچه‌سازی با رابط Editor1 انجام شده است.


## مدیریت تم‌های روشن و تاریک (Themes)

مدیریت تم‌ها مدیریت تم و استایل‌های پایه روشن و تاریک را در مسیر `alfacode/src/themes/` اضافه می‌کند. این مرحله ظاهر پایه ویرایشگر و رنگ‌بندی توکن‌های HTML، CSS و JavaScript را از طریق CSS custom properties فراهم می‌کند؛ هنوز اتصال نهایی این تم‌ها به صفحه اصلی Editor1 در این مرحله انجام نشده است.

### ThemeManager

فایل `src/themes/theme-manager.js` شامل کلاس `ThemeManager` است:

- `new ThemeManager(options)` دو تم پیش‌فرض `dark` و `light` را ثبت می‌کند و به‌صورت پیش‌فرض تم `dark` را فعال می‌کند.
- گزینه‌های سازنده: `defaultTheme`، `rootElement` و `themes` برای تعیین تم آغازین، عنصر ریشه اختیاری و ثبت تم‌های افزوده.
- `register(theme)` تمی با شناسه یکتا و کلاس CSS معتبر ثبت می‌کند. شیء تم شامل `id` و گزینه‌های `label` و `className` است.
- `get(id)`، `has(id)` و `list()` برای دریافت و فهرست تم‌ها هستند.
- `setTheme(id, rootElement)` تم فعال را تغییر می‌دهد و در صورت ارائه عنصر DOM، کلاس تم را روی آن اعمال می‌کند.
- `apply(rootElement)` تم فعال را روی یک عنصر DOM اعمال می‌کند.
- `unregister(id)` تم غیرفعال را حذف می‌کند؛ حذف تم فعال مجاز نیست.
- `clear(rootElement)` کلاس و ویژگی تم را از عنصر ریشه پاک می‌کند و وضعیت فعال را بازنشانی می‌کند.
- این ماژول به `document` سراسری یا API شبکه وابسته نیست؛ عنصر DOM فقط از طریق آرگومان صریح دریافت می‌شود.

### فایل‌های CSS و قرارداد ظاهر

- `src/themes/dark.css`: پالت تیره و مقادیر متغیرهای CSS تم تاریک.
- `src/themes/light.css`: پالت روشن و مقادیر متغیرهای CSS تم روشن.
- `ThemeManager` فقط کلاس `alfacode-theme-dark` یا `alfacode-theme-light` و ویژگی `data-alfacode-theme` را روی ریشه اعمال می‌کند؛ بارگذاری فایل‌های CSS باید به‌صورت محلی توسط مصرف‌کننده پروژه انجام شود.
- متغیرهای مشترک با پیشوند `--alfacode-` تعریف شده‌اند و سطح پس‌زمینه، متن، انتخاب، مکان‌نما، شماره خطوط، تطبیق پرانتزها و رنگ گروه‌های معنایی توکن‌ها را پوشش می‌دهند.
- کلاس‌های رنگ‌بندی با خروجی واقعی `SyntaxHighlighter` هماهنگ‌اند؛ از جمله `alfacode-token--keyword`، `alfacode-token--tag`، `alfacode-token--string`، `alfacode-token--comment` و `alfacode-token--invalid`.
- کلاس‌های `alfacode-editor-view`، `alfacode-line`، `alfacode-line-content`، `alfacode-selection`، `alfacode-cursor` و کلاس‌های شماره خطوط با اجزای موجود هماهنگ شده‌اند.
- کلاس CSS عمومی `alfacode-bracket-match` برای نمایش جفت پرانتز در یکپارچه‌سازی با رابط Editor1 به چرخه رندر متصل شده است.

### وضعیت بررسی

فایل‌های ThemeManager و دو stylesheet از نظر ساختار، اعتبارسنجی ورودی‌ها و تطبیق نام کلاس‌ها با ماژول‌های موجود بازبینی ایستا شده‌اند. آزمون اجرایی و بررسی واقعی ظاهر در مرورگر هنوز انجام نشده است و در آزمون‌های پایه و یکپارچه‌سازی بعدی بررسی خواهد شد.


## آزمون‌های پایه — آزمون اجزا و تعامل ماژول‌ها

آزمون‌های پایه آغاز شده است. مجموعه آزمون خودکار اولیه در `alfacode/tests/alfacode.test.mjs` ایجاد شده و گردش‌کار GitHub Actions در `.github/workflows/alfacode-tests.yml` برای اجرای آن روی تغییرات مرتبط تنظیم شده است.

آزمون‌های فعلی مدل سند و offsetهای UTF-16، انتخاب متن، تراکنش اتمی، تاریخچه Undo/Redo، هماهنگی Editor، ورودی صفحه‌کلید و چرخه اتصال InputController، ثبت زبان‌ها، اعتبارسنجی توکن‌ها، ParserManager، تحلیل نمونه HTML/CSS/JavaScript، تطبیق پرانتزها و مدیریت تم‌ها را پوشش می‌دهند.

فرمان اجرای محلی در ریشه مخزن:

```bash
node --experimental-default-type=module --test alfacode/tests/alfacode.test.mjs
```

در نخستین اجرای واقعی GitHub Actions، ۱۷ آزمون از ۱۸ آزمون موفق شدند و آزمون جفت‌سازی براکت‌های متقاطع (`([)]`) شکست خورد. منطق `BracketMatcher` اصلاح شد تا با مشاهده بستار ناسازگار، پشته بازکننده‌های معلق را باطل کند. اجرای مجدد GitHub Actions روی commit اصلاحی با موفقیت پایان یافت: هر ۱۸ آزمون موفق و صفر آزمون ناموفق بود. بنابراین آزمون‌های خودکار پایه آزمون‌های پایه تأیید شده‌اند. آزمون DOM واقعی مرورگر، IME فارسی، کارایی اسناد بزرگ و رفتار کامل رندر همچنان به بررسی تکمیلی نیاز دارند.


## تکمیل یکپارچه‌سازی AlfaCode — یکپارچه‌سازی با رابط Editor1

یکپارچه‌سازی با رابط Editor1 تکمیل شده است. موتور اختصاصی از طریق ماژول‌های ES به بخش Editor متصل است و مرزبندی مسئولیت‌ها حفظ شده است:

- `core/editor/`: ساخت نمونه `Editor`، نمایش `EditorView`، دریافت ورودی با `InputController` و مدیریت زبان‌های HTML، CSS و JavaScript.
- `script.js`: هماهنگ‌کننده اصلی میان iframe ویرایشگر و iframe پیش‌نمایش؛ پیام تغییر کد را اعتبارسنجی و آخرین خروجی را تا آماده‌شدن Preview نگهداری می‌کند.
- `core/preview/`: نمایش HTML، CSS و JavaScript در iframe مستقل با `sandbox="allow-scripts"` و بدون مجوز `allow-same-origin`.
- `SyntaxHighlighter`، `LineNumbers` و `BracketMatcher` به چرخه رندر متصل‌اند.
- انتخاب متن و مکان‌نما میان DOM مرورگر و مدل سند همگام می‌شوند؛ ورودی و حذف محدوده انتخاب‌شده نیز در بررسی دستی کاربر تأیید شده‌اند.
- gutter و متن کد از میزبان اسکرول مشترک استفاده می‌کنند و معیار ارتفاع خطوط در CSS هماهنگ شده است.
- ورودی در حال composition باعث رندر زودهنگام نمی‌شود و متن نهایی در پایان composition به سند منتقل می‌شود.

آزمون‌های خودکار موتور و بررسی نحوی فایل‌های اتصال در GitHub Actions موفق بوده‌اند؛ هر ۱۸ آزمون پایه با صفر خطا اجرا شده‌اند. [گزارش CI](https://github.com/alfamaniya/Editor1/actions/runs/44090566282). رفتار پایه مکان‌نما، جابه‌جایی و حذف انتخاب نیز توسط کاربر در نسخه منتشرشده بررسی شده است. آزمون اختصاصی IME فارسی روی دستگاه واقعی در این محیط قابل شبیه‌سازی نیست و به‌عنوان بررسی تکمیلی دستگاه ثبت می‌شود؛ این مورد مانع تکمیل اتصال پایه یکپارچه‌سازی با رابط Editor1 نیست.

## تکمیل بررسی اجرای آفلاین — ممیزی اجرای آفلاین

ممیزی اجرای آفلاین از نظر ساختار منابع، وابستگی‌ها، اجرای محلی و گردش‌کار انتشار تکمیل شده است:

- صفحه اصلی فقط فایل‌های محلی `style.css` و `script.js` را بارگذاری می‌کند.
- صفحه Editor فایل‌های CSS محلی، stylesheetهای تم محلی و ماژول‌های AlfaCode با مسیرهای نسبی را بارگذاری می‌کند.
- صفحه Preview و هماهنگ‌کننده اصلی نیز فایل‌های محلی هستند؛ خروجی کاربر در iframe دارای sandbox اجرا می‌شود.
- در فایل‌های اجرایی و stylesheetهای بررسی‌شده، ارجاع ضروری به CDN، کتابخانه خارجی، فونت شبکه‌ای یا سرویس راه دور وجود ندارد.
- اجرای آفلاین باید از طریق سرور محلی انجام شود تا محدودیت مرورگر برای ES Modules در `file://` ایجاد نشود؛ راه‌اندازی سرور به اینترنت وابسته نیست.
- آزمون نحوی JavaScript، ۱۸ آزمون پایه AlfaCode و ساخت و انتشار GitHub Pages موفق بوده‌اند. [گزارش ساخت و انتشار Pages](https://github.com/alfamaniya/Editor1/actions/runs/44090603909).

**نتیجه:** توسعه و یکپارچه‌سازی اولیه AlfaCode تکمیل شده است. آزمون دستی IME فارسی و سنجش کارایی روی فایل‌های بسیار بزرگ، ارزیابی‌های تکمیلی برای دستگاه و مرورگر واقعی هستند و به‌عنوان نقص پنهان یا آزمون انجام‌شده گزارش نمی‌شوند.

گردش‌کار `.github/workflows/build-offline.yml` فایل اجرایی مستقل `offline/AlfaCode-Offline.html` را می‌سازد.

- با هر تغییر مرتبط در رابط کاربری یا سورس موتور روی شاخه `main`، ساخت به‌صورت خودکار اجرا می‌شود.
- اجرای دستی نیز از بخش **Actions → Build AlfaCode Offline → Run workflow** در GitHub امکان‌پذیر است.
- ماژول‌های ES موتور با نسخه ثابت esbuild در زمان ساخت bundle می‌شوند؛ CSS و JavaScript رابط، هدر، تقسیم‌کننده و Preview نیز در HTML نهایی جای‌گذاری می‌شوند.
- خروجی نهایی به فایل‌های جانبی، CDN، سرور محلی یا اتصال اینترنت در زمان اجرا وابسته نیست و برای اجرا باید فایل HTML را در مرورگر باز کرد.
- فایل‌های مستندات و آزمون‌ها در خروجی اجرایی وارد نمی‌شوند.
- ساخت، ارجاعات خارجی و وجود بخش‌های اصلی سند را اعتبارسنجی می‌کند. گزارش تعداد فایل‌های ورودی و حجم منبع و خروجی در گزارش اجرای GitHub Actions ثبت می‌شود.
- در پایان ساخت، فایل خروجی در پوشه `offline/` به شاخه `main` commit می‌شود. commit خروجی به‌تنهایی باعث اجرای دوباره این گردش‌کار نمی‌شود.

**محدوده تأیید:** ساخت و اعتبارسنجی خودکار فایل به‌وسیله workflow انجام می‌شود. اجرای واقعی فایل تولیدشده با دوبار کلیک در مرورگرهای مقصد باید پس از اولین خروجی نیز به‌صورت دستی بررسی شود؛ تا پیش از آن، سازگاری مرورگر به‌عنوان آزمون عملی تأییدشده گزارش نمی‌شود.


## ارسال نسخه آفلاین به ایمیل شرکت

گردش‌کار دستی `.github/workflows/send-offline-email.yml` آخرین نسخه `offline/AlfaCode-Offline.html` را از مخزن می‌خواند و محتوای آن را از طریق Gmail به نشانی `a.mamghanian@isaco.ir` ارسال می‌کند.

- اجرا فقط با انتخاب دستی گردش‌کار **Send AlfaCode Offline by Gmail** از زبانه Actions انجام می‌شود؛ با push یا تغییر فایل‌ها ایمیلی ارسال نمی‌شود.
- اسکریپت `scripts/send-offline-email.py` محتوای UTF-8 فایل را اعتبارسنجی می‌کند و کل آن را بدون تقسیم‌بندی و بدون ضمیمه، در بدنه یک ایمیل متنی با موضوع `AlfaCode Offline` قرار می‌دهد.
- کل متن فایل در یک پیام و از طریق اتصال امن TLS به سرور SMTP گوگل ارسال می‌شود. هیچ عنوان، شماره بخش یا متن توضیحی به محتوای کد اضافه نمی‌شود.
- برای فعال‌سازی، در تنظیمات مخزن به مسیر **Settings → Secrets and variables → Actions → New repository secret** بروید و دو Secret زیر را بسازید:
  - `GMAIL_USERNAME`: آدرس کامل حساب Gmail فرستنده.
  - `GMAIL_APP_PASSWORD`: رمز اختصاصی برنامه گوگل (App Password)، نه رمز اصلی حساب.
- ایجاد App Password در حساب گوگل به فعال بودن تأیید دومرحله‌ای (2-Step Verification) نیاز دارد. این رمز را فقط در GitHub Secrets وارد کنید و آن را در کد، README یا پیام‌ها قرار ندهید.
- برای ارسال، از مسیر **Actions → Send AlfaCode Offline by Gmail → Run workflow** گردش‌کار را اجرا کنید. نتیجه و تعداد ایمیل‌های ارسال‌شده در گزارش اجرا ثبت می‌شود.
- این گردش‌کار فقط مجوز خواندن مخزن دارد و هیچ فایلی را تغییر یا commit نمی‌کند. اگر ارسال در میانه کار با خطا مواجه شود، اجرای workflow ناموفق اعلام می‌شود؛ ممکن است ایمیل‌های بخش‌های قبلی قبلاً ارسال شده باشند.

## نمونه آغازین ویرایشگر

ویرایشگر با یک نمونه کامل و هماهنگ در هر سه تب باز می‌شود. تب HTML ساختار صفحه نمونه را نگه می‌دارد، تب CSS ظاهر کارت و اجزای آن را تعریف می‌کند و تب JavaScript رفتار دکمه شمارنده را پیاده‌سازی می‌کند. هیچ‌کدام از استایل‌ها یا کدهای رفتاری نمونه داخل HTML قرار نگرفته‌اند؛ هر زبان در بافر مستقل خودش نگهداری می‌شود.

با جابه‌جایی میان تب‌ها، محتوای هر زبان حفظ می‌شود. Live Preview نیز سه منبع HTML، CSS و JavaScript را با هم ترکیب می‌کند؛ بنابراین تغییر استایل یا رفتار، بدون نیاز به انتقال کد به تب HTML در خروجی قابل مشاهده است.


## ذخیره‌سازی خودکار در مرورگر

کدهای سه تب HTML، CSS و JavaScript به‌صورت خودکار و با تأخیر کوتاه در `localStorage` مرورگر ذخیره می‌شوند. با بارگذاری دوباره صفحه، آخرین نسخه معتبر هر سه منبع بازیابی می‌شود. وضعیت ذخیره‌سازی در نوار پایین ویرایشگر نمایش داده می‌شود. داده‌ها فقط در همان مرورگر و همان مبدأ (origin) در دسترس‌اند؛ پاک‌کردن داده‌های سایت یا مرورگر می‌تواند آن‌ها را حذف کند. این قابلیت به اینترنت یا سرویس بیرونی وابسته نیست.

منطق ذخیره‌سازی در `core/browser-storage/` مستقل از هسته موتور AlfaCode قرار دارد و فایل مستقل آفلاین نیز از طریق گردش‌کار ساخت پروژه با همین قابلیت تولید می‌شود.


## رابط کاربری موبایل

در نمایشگرهای با عرض حداکثر ۷۰۰ پیکسل، محیط کار به‌صورت تک‌پنجره‌ای نمایش داده می‌شود. کاربر با نوار جابه‌جایی موبایل بین Editor و Preview حرکت می‌کند؛ در این حالت تقسیم‌کننده دو پنل پنهان است و هر بخش تمام فضای کاری را می‌گیرد. در نمایشگرهای بزرگ‌تر، چیدمان دوپنلی و تقسیم‌کننده قابل‌جابه‌جایی بدون تغییر باقی می‌ماند.
