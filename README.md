# Editor1

Editor1 یک محیط تحت وب برای نوشتن و اجرای کدهای HTML، CSS و JavaScript است. محیط شامل ویرایشگر کد و پیش‌نمایش زنده است و برای استفاده در مرورگر دسکتاپ و موبایل طراحی شده است.

## وضعیت پروژه

| بخش | وضعیت مستند |
|---|---|
| محیط اصلی ویرایشگر و پیش‌نمایش زنده | پیاده‌سازی شده |
| تب‌های مستقل HTML، CSS و JavaScript | پیاده‌سازی شده |
| ذخیره خودکار در مرورگر | پیاده‌سازی شده؛ محدود به همان مرورگر و مبدأ |
| چیدمان دسکتاپ و تقسیم‌کننده قابل جابه‌جایی | پیاده‌سازی شده |
| رابط تک‌پنجره‌ای موبایل و کلیدهای کمکی | پیاده‌سازی شده |
| پیشنهادهای HTML، CSS و JavaScript | پیاده‌سازی اولیه؛ برخی آزمون‌های واقعی دستگاه/مرورگر باقی است |
| صفحه کاتالوگ تکمیل خودکار | پیاده‌سازی اولیه؛ مسیر مدیریت و انتشار هنوز کامل نشده |
| آزمون داده مرجع کاتالوگ | زیرمرحله ۲-۲-۱ (بررسی زیرساخت و طراحی آزمون) تکمیل؛ اجرای اعتبارسنجی هنوز آغاز نشده |
| بسته مستقل آفلاین | فرایند ساخت و فایل خروجی وجود دارد؛ آزمون دستی روی دستگاه کاربر جداگانه لازم است |
| ارسال ایمیل نسخه آفلاین | workflow دستی وجود دارد؛ ارسال واقعی باید جداگانه تأیید شود |

این جدول وضعیت مستندات و پیاده‌سازی شناخته‌شده را نشان می‌دهد؛ موفقیت CI به‌تنهایی به معنی آزمون واقعی در مرورگر یا دستگاه کاربر نیست.

## معماری مخزن

- `index.html`، `style.css` و `script.js`: پوسته و هماهنگ‌کننده محیط اصلی.
- `core/`: قابلیت‌های مستقل رابط کاربری؛ هر قابلیت در پوشه خودش نگهداری می‌شود.
- `alfacode/`: موتور مستقل ویرایشگر، زبان‌ها، آزمون‌ها و مستند فنی.
- `scripts/`: ابزارهای ساخت بسته آفلاین و ارسال ایمیل.
- `offline/`: خروجی مستقل تولیدشده.
- `.github/workflows/`: آزمون‌ها، ساخت بسته آفلاین و ارسال دستی ایمیل.

### ماژول‌های اصلی رابط

`core/` شامل پوشه‌های `editor`، `preview`، `header`، `workspace-divider`، `mobile-workspace`، `mobile-extra-keys`، `browser-storage`، `clear-tabs`، `project-reset`، `clear-project-cookies`، `tag-suggestions`، `css-suggestions`، `javascript-suggestions`، `completion-catalog` و `new-page-action` است.

هر قابلیت مستقل باید در پوشه خودش نگهداری شود. فایل‌های ریشه نباید محل انباشته‌شدن منطق اختصاصی قابلیت‌ها شوند.

## اجرای پروژه

برای اجرای نسخه توسعه، مخزن را دریافت و با یک سرور محلی ایستا اجرا کنید. به دلیل استفاده از JavaScript modules، اجرای مستقیم `index.html` با نشانی `file://` روش اجرای توسعه نیست.

نمونه با Python:

```bash
python -m http.server 8000
```

سپس نشانی `http://localhost:8000` را در مرورگر باز کنید.

## بسته مستقل آفلاین

فایل `offline/AlfaCode-Offline.html` از سورس پروژه تولید می‌شود. اسکریپت ساخت در `scripts/build-offline.mjs` قرار دارد و workflow مربوط در `.github/workflows/build-offline.yml` است. خروجی باید مستقل باشد و برای اجرای قابلیت‌های بسته به فایل JavaScript یا CSS خارجی نیاز نداشته باشد.

پس از تغییر سورس، خروجی آفلاین باید از مسیر ساخت مجدداً تولید شود؛ ویرایش دستی خروجی جایگزین اصلاح سورس نیست.

## گردش‌کارهای GitHub

- `alfacode-tests.yml`: بررسی syntax فایل‌های یکپارچه‌سازی و اجرای آزمون‌های خودکار AlfaCode.
- `build-offline.yml`: ساخت خروجی مستقل آفلاین.
- `send-offline-email.yml`: اجرای دستی ارسال نسخه آفلاین از طریق ایمیل؛ تنظیم Secrets لازم است.

نتیجه هر workflow باید از صفحه Actions مخزن بررسی شود. workflow موفق، آزمون دستی مرورگر و دستگاه را جایگزین نمی‌کند.

## قواعد توسعه پروژه

1. هر قابلیت مستقل باید پوشه جداگانه داشته باشد.
2. در صورت تناسب با نوع قابلیت، فایل‌های HTML، CSS و JavaScript آن در همان پوشه قرار می‌گیرند.
3. منطق اختصاصی قابلیت‌ها در فایل‌های ریشه قرار نگیرد.
4. تغییرات فقط پس از تأیید مدیر پروژه انجام شوند و هر کار به زیرمرحله‌های کوچک تقسیم شود.
5. پیش از تغییر فایل موجود در GitHub، نسخه جاری و SHA آن دریافت شود.
6. پس از هر تغییر کد یا ساختار، این README و README اختصاصی AlfaCode با وضعیت واقعی هماهنگ شوند.
7. هیچ قابلیت یا آزمونی که اجرا نشده، تکمیل‌شده یا موفق اعلام نشود.
8. نسخه آفلاین باید از سورس اصلی تولید شود.
