# معماری CSS و JavaScript — Editor1

این سند قانون رسمی معماری فایل‌های ظاهر (CSS) و رفتار (JavaScript) پروژه است.

## قانون ۱: CSS صفحه/بخش، یک فایل مشخص

- هر صفحه یا بخش UI مستقل و بزرگ می‌تواند **یک فایل CSS اختصاصی برای ظاهر همان صفحه/بخش** داشته باشد؛ مانند صفحه Editor، Preview یا Catalog.
- CSS باید بر اساس صفحه/بخش یا ماژول UI سازمان‌دهی شود، نه بر اساس هر اکشن یا دکمه.
- از ایجاد CSS جدا برای قابلیت کوچک، دکمه، رویداد یا عنصر تکی خودداری شود.
- CSS هر بخش فقط مسئول ظاهر همان بخش باشد و با selectorهای scoped از سایر قسمت‌ها اثر ناخواسته نگذارد.

## قانون ۲: عناصر مشابه، استایل مشترک

- المان‌های هم‌نوع و هم‌نقش باید از کلاس‌ها و قواعد مشترک استفاده کنند؛ مانند دکمه‌ها، ورودی‌ها، تب‌ها، پنل‌ها، popupها و برچسب‌ها.
- استایل تکراری با مقادیر یا نام‌های مختلف نسازید.
- تفاوت‌های ضروری با modifier کلاس یا CSS variables پیاده شود، نه کپی‌کردن بلوک استایل.
- پیش از نوشتن CSS، فایل استایل مرتبط را بررسی کنید و قواعد موجود را reuse کنید.

## قانون ۳: JavaScript قابلیت‌ها و اکشن‌ها مستقل

- قابلیت‌هایی که اکشن، رویداد، تعامل، مدیریت وضعیت یا منطق اجرایی دارند می‌توانند فایل JavaScript مستقل داشته باشند.
- JavaScript هر قابلیت از ظاهر آن جدا باشد؛ JS مسئول منطق و رفتار است، CSS مسئول ظاهر.
- فایل JS جدا برای اکشن‌های مستقل (مانند Reset، New Page، پاک‌سازی تب‌ها یا ذخیره‌سازی) مجاز و ترجیح داده می‌شود.
- فایل JS نباید استایل‌های inline یا تولید CSS پراکنده کند، مگر در مواردی که تغییرات کاملاً دینامیک و ضروری باشد؛ در آن موارد تا حد امکان از کلاس‌ها و متغیرهای تعریف‌شده در CSS استفاده شود.

## قانون ۴: صفحات iframe و اجزای جدا

- اگر صفحه‌ای در iframe اجرا می‌شود، CSS مربوط به آن صفحه باید در سند iframe بارگذاری شود؛ صفحه والد نمی‌تواند مستقیماً عناصر داخلی iframe را استایل کند.
- Web Component یا ماژول بودن به‌تنهایی مجوز ایجاد CSS مستقل برای هر اکشن نیست.
- ساختار CSS و JS باید واضح، قابل ردیابی و سازگار با نسخه آنلاین و آفلاین باشد.

## قانون ۵: نگهداری و آزمون

- هنگام افزودن یا تغییر صفحه/بخش، فایل CSS همان صفحه/بخش را به‌روزرسانی کنید؛ در صورت وجود عناصر مشترک، قواعد مشترک موجود را reuse کنید.
- هنگام تغییر اکشن/قابلیت، JS مستقل آن را حفظ یا اصلاح کنید و از ساخت CSS اختصاصی برای آن اکشن خودداری کنید.
- در هر تغییر، README و `maps/ROADMAP.md` به‌روزرسانی شوند.
- CSS/JS قدیمی فقط پس از انتقال کامل، اصلاح import/linkها و تست‌های مرتبط حذف شوند.
- تست پذیرش: ظاهر هر صفحه/بخش در فایل CSS مشخص آن قابل ردیابی باشد، منطق اکشن‌ها در JS جدا باشد، عناصر مشابه استایل مشترک داشته باشند، و نسخه آنلاین و آفلاین رفتار یکسان داشته باشند.

## الگوی پیشنهادی

```
page-or-module/
├── page.html
├── page.css  # ظاهر این صفحه/بخش
└── feature.js # منطق/اکشن‌ها (در صورت نیاز؛ می‌تواند چند JS مستقل داشته باشد)
```

برای پروژه Editor1، CSS صفحه‌ها/بخش‌های اصلی می‌تواند فایل‌های مستقل داشته باشد؛ اکشن‌ها و قابلیت‌های دارای منطق در JS جدا باقی بمانند. استایل‌های مشترک باید reuse شوند و CSS تکراری ایجاد نشود.
