# برنامه تکمیل و اعتبارسنجی پیشنهاد تگ‌های HTML

## هدف
تعیین و انجام کارهای باقیمانده قابلیت پیشنهاد تگ HTML در AlfaCode، بدون بازنویسی قابلیت‌های موجود و بدون تغییر رفتار تأییدشده کاربر.

## وضعیت فعلی بر اساس مستندات و کد ثبت‌شده
- موتور پیشنهاد تگ و رابط منوی پیشنهاد در مخزن وجود دارند.
- منوی پیشنهاد تا ۱۰ گزینه نمایش می‌دهد و فیلتر پیشوندی و قواعد زمینه‌ای دارد.
- پذیرش با صفحه‌کلید و درج تگ‌های معمولی/void و تنظیم مکان‌نما پیاده‌سازی شده است.
- پیشنهاد زنجیره‌ای اولیه پس از درج تگ جفتی وجود دارد.
- ۲۶ آزمون خودکار موتور در CI گزارش موفق داشته‌اند.
- ساخت خروجی آفلاین شامل موتور و منوی پیشنهاد قبلاً در CI موفق گزارش شده است.
- آزمون واقعی مرورگر، لمس روی دستگاه و IME فارسی هنوز به‌عنوان آزمون دستگاهی تأیید نشده است.
- قواعد context موجود کامل و معادل الگوریتم content model استاندارد WHATWG نیستند.

## محدوده
این برنامه فقط تکمیل موارد باقی‌مانده و راستی‌آزمایی رفتار موجود را پوشش می‌دهد. بازنویسی موتور، تغییر اولویت تگ‌ها یا افزودن قابلیت جدید بدون تأیید مدیر پروژه مجاز نیست.

## مسیرها و فایل‌های مرتبط
| مسیر | نقش |
|---|---|
| `alfacode/src/language/html/html-completion.js` | موتور پیشنهاد و منطق زمینه |
| `alfacode/src/language/html/html-rules.js` | قواعد و عناصر HTML |
| `core/tag-suggestions/` | رابط سه‌فایلی منوی پیشنهاد |
| `alfacode/tests/` | آزمون‌های خودکار |
| `scripts/build-offline.mjs` | ساخت نسخه مستقل آفلاین |
| `offline/AlfaCode-Offline.html` | خروجی آفلاین تولیدشده |

## مراحل اجرایی

### مرحله ۱ — ممیزی وضعیت واقعی قبل از هر تغییر
- [ ] بررسی کد جاری موتور و رابط پیشنهاد
- [ ] بررسی آزمون‌های موجود و پوشش موارد کلیدی
- [ ] بررسی workflow و آخرین نتیجه CI مرتبط
- [ ] تطبیق رفتار واقعی کد با توضیحات این برنامه
- [ ] ثبت اختلاف‌ها؛ بدون اصلاح خودکار

### مرحله ۲ — آزمون تعاملی در مرورگر
- [ ] تدوین سناریوهای نمایش، فیلتر و انتخاب پیشنهاد
- [ ] آزمون Enter، Tab، Escape و کلیدهای جهت‌دار
- [ ] آزمون درج تگ معمولی و void و محل مکان‌نما
- [ ] آزمون زنجیره پیشنهاد فرزند و رفتن به تگ پایانی
- [ ] آزمون Undo/Redo و جلوگیری از درج تکراری
- [ ] آزمون نمایش و اسکرول منو در اندازه موبایل و دسکتاپ
- [ ] آزمون IME فارسی و ترکیب حروف
- [ ] ثبت نتایج واقعی، مرورگر، دستگاه و موارد شکست

### مرحله ۳ — ارزیابی پوشش قواعد زمینه‌ای
- [ ] تهیه ماتریس contextهای پیاده‌سازی‌شده
- [ ] مقایسه با دسته‌های اصلی content model در استاندارد WHATWG
- [ ] شناسایی موارد ناقص با مثال بازتولیدپذیر
- [ ] اولویت‌بندی نقص‌ها و ارائه پیشنهاد اصلاح به مدیر پروژه
- [ ] دریافت تأیید پیش از تغییر قواعد یا موتور

### مرحله ۴ — اصلاحات تأییدشده و آزمون بازگشتی
- [ ] فقط اصلاحات صریحاً تأییدشده اجرا شوند
- [ ] آزمون‌های واحد و بازگشتی اضافه/اصلاح شوند
- [ ] CI و build آفلاین اجرا شوند
- [ ] رفتار مرورگر پس از اصلاح دوباره بررسی شود
- [ ] READMEها و این برنامه مطابق نتیجه واقعی به‌روز شوند

## معیار تکمیل
سناریوهای تعاملی روی مرورگر/دستگاه مشخص اجرا و ثبت شده باشند؛ محدودیت‌های context شناسایی و تعیین تکلیف شده باشند؛ هیچ رفتار موجود بدون تأیید تغییر نکرده باشد؛ و آزمون‌های خودکار و build مرتبط نتیجه مستند داشته باشند.
