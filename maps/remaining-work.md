### اتصال واقعی کاتالوگ‌های JSON به Editor (۱۹ نوامبر ۲۰۲۶)
- Loader مشترک در راه‌اندازی `core/editor/editor.js` بارگذاری می‌شود و رکوردهای سه زبان به موتور پیشنهاد مربوط ارسال می‌شوند.
- HTML از JSON برای HTML/SVG استفاده می‌کند و پیشنهادهای Legacy را به‌عنوان سازگاری پایه حفظ می‌کند؛ درج تگ، close و chain بدون تغییر قرارداد UI باقی مانده‌اند.
- CSS پیشنهادهای property، selector، value، at-rule، function و unit را از رکوردهای JSON می‌گیرد.
- JavaScript پیشنهادهای identifier و member را از رکوردهای JSON و owner مربوط می‌گیرد؛ Snippet و literal هنوز در مسیر درج زنده فعال نشده‌اند.
- تست runtime مستقل اضافه شده است؛ نتیجه CI پس از اجرای workflow باید ثبت شود.

### وضعیت پیاده‌سازی Runtime و Offline (۱۹ نوامبر ۲۰۲۶)
- هر سه JSON به Editor متصل‌اند؛ Loader در محیط وب JSON را بارگذاری می‌کند و در نسخه آفلاین داده‌های تعبیه‌شده را بدون fetch مصرف می‌کند.
- HTML/SVG: داده‌های JSON با حفظ گزینه‌های سازگاری Legacy و قرارداد درج به موتور وصل شده‌اند.
- CSS: شش گروه selector، property، value، at-rule، function و unit در موتور فعال‌اند.
- JavaScript: identifier، literal و memberهای دارای owner در موتور فعال‌اند؛ Snippetها عمداً غیرفعال مانده‌اند.
- تست CI: ۹۲ موفق، صفر شکست. Offline Build موفق و خروجی offline/AlfaCode-Offline.html بازسازی شده است.
- آزمون دستی مرورگر، IME، Cursor و قطع اینترنت هنوز باید انجام شود.

### نتیجه بررسی موتور HTML (۱۹ نوامبر ۲۰۲۶)
- موتور پیشنهاد HTML در `alfacode/src/language/html/html-completion.js` از آرایه ثابت `HTML_TAG_CATALOG` و قواعد context استفاده می‌کند؛ هنوز از JSON تکمیل HTML تغذیه نمی‌شود.
- `core/editor/editor.js` مستقیماً `getHTMLTagSuggestions(...)` را فراخوانی و نتیجه را به منوی `createTagSuggestions` می‌دهد.
- `core/completion-catalog/catalog-loader.js` برای JSONها وجود دارد، اما اتصال آن به موتور HTML در این مسیر مشاهده نشد.
- این بررسی فقط خواندنی بود؛ هیچ کد اجرایی تغییر نکرد.


### نتیجه بررسی Loader مشترک (۱۹ نوامبر ۲۰۲۶)
- `core/completion-catalog/catalog-loader.js` سه JSON را با URLهای نسبی مبتنی بر `import.meta.url` بارگذاری می‌کند.
- هر سه درخواست به‌صورت موازی اجرا می‌شوند؛ پاسخ ناموفق یا JSON/schema نامعتبر برای همان زبان به `records: []` و `error` تبدیل می‌شود.
- اعتبارسنجی فعلی فقط وجود آرایه `records` را بررسی می‌کند؛ رکوردها با شرط `enabled !== false` و داشتن `label` رشته‌ای فیلتر می‌شوند و زبان به رکوردها افزوده می‌شود.
- خروجی شامل `sourceCount`، `catalogVersion` و `error` است. گزینه `cache: no-store` برای درخواست‌ها تنظیم شده است.
- Loader در صفحه کاتالوگ استفاده شده؛ اما اتصال runtime به موتور HTML در این بررسی تأیید نشد. Loader خودش آزمون مستقل یا اعتبارسنجی عمیق فیلدها ندارد.
- فقط بررسی انجام شد؛ فایل Loader تغییر نکرد.


### نتیجه بررسی اتصال موتور HTML به Editor (۱۹ نوامبر ۲۰۲۶)
- `editor.js` در `updateCompletionSuggestions()` صدا می‌زند: `getHTMLTagSuggestions(editor.text, editor.selection.head, { chain: chainSuggestionMode, limit: 10 })`؛ متن کامل، offset کرسر، حالت زنجیره‌ای و محدودیت ۱۰ گزینه ارسال می‌شود.
- نتیجه به منوی `createTagSuggestions` منتقل می‌شود؛ منو نمایش، انتخاب و پیمایش گزینه‌ها را مدیریت می‌کند.
- `applyTagSuggestion()` از `option.from` و `option.to` برای جایگزینی استفاده می‌کند؛ تگ باز را همراه تگ بسته (در صورت void نبودن) درج می‌کند و Cursor را بعد از تگ باز قرار می‌دهد. حالت زنجیره‌ای برای پیشنهاد فرزند فعال می‌شود.
- کلیدهای Arrow Up/Down، Enter/Tab و Escape در `editor.js` مدیریت می‌شوند؛ انتخاب از طریق `applySuggestionForMenu` مسیریابی می‌شود.
- مسیر اتصال برای انتقال داده JSON قابل استفاده است، اما موتور فعلی هنوز کاتالوگ ثابت و قواعد context خودش را مصرف می‌کند. تبدیل به JSON باید قرارداد گزینه‌ها (`label`, `kind`, `isVoid`, `description`, `from`, `to`) و رفتار chain/close را حفظ کند.
- فقط بررسی انجام شد؛ فایل‌های اجرایی تغییری نکردند.

### نتیجه بررسی سازگاری JSON با موتور HTML (۱۹ نوامبر ۲۰۲۶)
- هر ۴۴ تگ کاتالوگ اصلی موتور در JSON وجود دارند؛ نام‌های موتور ثابت از JSON جاافتاده ندارند.
- JSON گسترده‌تر است: ۱۴۶ رکورد، ۱۴۵ نام یکتا؛ شامل عناصر HTML اضافی و ۳۵ رکورد SVG. تکرار title مربوط به namespace/context متفاوت است.
- موتور برای پیشنهادهای اصلی از rank و برای بعضی contextها rank محلی تولید می‌کند؛ JSON rank در ۶ رکورد ندارد (dt, dd, caption, colgroup, tfoot, optgroup). اتصال باید fallback رتبه‌بندی داشته باشد.
- JSON فیلدهای enabled، contexts، parentTags، namespace و isVoid دارد؛ موتور فعلی قواعد context جداگانه (head/root، والدها، p، SVG) دارد. قواعد باید در تبدیل JSON به candidates معادل‌سازی شوند و صرفاً enabled filtering کافی نیست.
- parentTags در ۶۰ رکورد موجود است؛ operation همه رکوردها open است. isVoid تعداد ۱۳ رکورد true و ۱۳۳ false.
- تفاوت rank و order در رکوردهای SVG عمدتاً ناشی از ترتیب سراسری JSON در برابر رتبه محلی SVG است؛ برای حفظ رفتار فعلی باید rank اولویت اصلی و order fallback باشد، نه جایگزین rank.
- پیشنهاد پیاده‌سازی: فیلتر enabled، انتخاب namespace/context، اعمال parentTags، استفاده از rank ?? order، نگه‌داشتن تولید گزینه‌ها و close/jump-close از منطق فعلی.
- فقط بررسی انجام شد؛ فایل‌های اجرایی و JSON تغییر نکردند.


### طرح تبدیل JSON به گزینه‌های موتور HTML (۱۹ نوامبر ۲۰۲۶)
- **Normalize:** رکورد فعال با `label` و `tagName` معتبر تبدیل به آیتم داخلی `name=tagName`، `rank=rank ?? order`، `description`، `void=isVoid`، `contexts`، `parentTags` و `namespace` شود؛ رکوردها با `enabled=false` حذف شوند.
- **Namespace/context:** هنگام حضور داخل SVG، فقط namespace=svg؛ در head، context= head؛ در root، context=root؛ در محتوای عادی، contextهای محدودکننده (اگر مشخص باشند) اعمال شوند. contextهای نامشخص/خالی برای بدنه به‌عنوان محدودیت جدید تفسیر نشوند تا پیشنهادهای قبلی ناخواسته حذف نگردند.
- **Parent-child:** اگر parentTags غیرخالی است، والد جاری باید با آن تطبیق داشته باشد؛ اگر خالی است، قواعد سازگاری فعلی موتور برای همان موقعیت حفظ شود تا داده‌های ناقص محدودکننده نشوند.
- **Ranking:** rank اولویت دارد؛ rank ناموجود به order و سپس ترتیب پایدار داده fallback کند. در contextهای اختصاصی مانند head/root/SVG، حفظ رتبه محلی و رفتار قبلی مهم است؛ از order سراسری SVG به‌تنهایی استفاده نشود.
- **Options contract:** خروجی UI ثابت بماند: label، kind، isVoid، description، from/to؛ حالت‌های child، close و jump-close همچنان از منطق فعلی ساخته شوند و صرفاً رکورد JSON پیشنهاد تگ بسته تولید نکند.
- **Migration:** ابتدا adapter فقط خواندنی و تست مقایسه‌ای با موتور legacy ساخته شود؛ اختلاف‌ها بررسی شوند؛ بعد از تطابق، JSON به‌عنوان منبع اصلی runtime قرار گیرد و حذف catalog ثابت مرحله‌ای و فقط پس از Regression انجام شود.
- **این مرحله طراحی است؛ هیچ فایل اجرایی تغییر نکرد.**


### ممیزی ریسک رفتاری اتصال JSON (۱۹ نوامبر ۲۰۲۶)
- **تگ بسته (close):** از stack سند ساخته می‌شود، نه catalog؛ نباید به JSON محدود شود. voidها نباید پیشنهاد بسته بگیرند.
- **Jump-close:** به تگ والد و جستجوی تگ بسته در ادامه متن وابسته است؛ منبع JSON نباید این منطق یا `closeTo` را حذف کند.
- **Chain/child:** در حالت chain رتبه محلی، limit و گزینه jump-close با هم محاسبه می‌شوند؛ rankهای JSON ممکن است ترتیب فعلی محلی والدها (مثل table، list، select) را تغییر دهند.
- **Head/root:** فهرست‌های head و root در موتور فعلی محدود و رتبه محلی‌اند؛ contexts/parentTags به تنهایی ممکن است پیشنهاد اضافی یا حذف‌شده ایجاد کنند. همچنین تگ‌های ساختاری حاضر در متن برای جلوگیری از تکرار بررسی می‌شوند.
- **SVG:** موتور فعلی هنگام قرار گرفتن stack در SVG از فهرست محدود ۱۰ تایی استفاده می‌کند؛ کاتالوگ JSON شامل ۳۵ رکورد SVG است. استفاده کامل JSON پوشش و ترتیب را تغییر می‌دهد و باید تصمیم محصول/آزمون تطبیق جداگانه داشته باشد.
- **Phrasing داخل p:** فهرست فعلی whitelist مشخص دارد؛ داده JSON ممکن است عناصر جدیدی پیشنهاد کند که رفتار فعلی را تغییر می‌دهد. ابتدا whitelist و تفاوت‌ها آزموده شوند.
- **ParentTags:** اعمال سراسری این فیلد خطر حذف گزینه‌ها دارد، چون موتور در برخی contextها قواعد صریح دارد و بعضی رکوردها parentTags خالی‌اند؛ منطق fallback باید به‌صورت context-aware باشد.
- **Rank/order:** rank گاهی رتبه عمومی است و موتور در head، SVG و والدهای خاص رتبه محلی می‌دهد؛ تغییر مستقیم sort به rank/order می‌تواند ترتیب منو و گزینه‌های اول را تغییر دهد.
- **Insertion contract:** kindهای open/child/close/jump-close، from/to، isVoid و closeTo باید بدون تغییر بمانند تا درج، Cursor و chain خراب نشوند.
- **توصیه:** adapter ابتدا در تست shadow اجرا شود؛ خروجی قدیم/جدید در contextهای root، body، head، p، list، table، select و SVG مقایسه و اختلاف‌ها دسته‌بندی شوند؛ سپس runtime switch.
- **این مرحله ممیزی است؛ فایل اجرایی تغییر نکرد.**


### طرح آزمون مقایسه‌ای Shadow برای HTML (۱۹ نوامبر ۲۰۲۶)
- **اصل آزمون:** در یک ورودی/offset واحد، خروجی legacy و adapter JSON محاسبه شود؛ هیچ خروجی جدیدی به UI ارسال نشود و legacy منبع رفتار فعال بماند.
- **Fixtureهای context:** root خالی و root دارای html/head/body؛ body معمولی؛ head؛ داخل p؛ ul/ol/menu؛ dl؛ table و tbody/thead/tfoot/tr؛ select و optgroup؛ SVG و زیرعنصر SVG.
- **Fixtureهای تکمیل:** prefix خالی و prefix چندحرفی، opening، closing، chain، وجود تگ ساختاری تکراری، تگ void، متن/attribute/comment، script/style raw text، تگ ناقص و cursor در ابتدا/انتهای متن.
- **مقایسه خروجی:** mode/context/from/to؛ تعداد گزینه؛ label و ترتیب؛ kind؛ isVoid؛ description؛ closeTo. اختلاف‌ها طبقه‌بندی شوند: مورد قابل قبول (گسترش کاتالوگ)، regression، اختلاف رتبه، اختلاف context/namespace، اختلاف قرارداد UI.
- **معیار قبولی:** هیچ regression در رفتار legacy و درج/جابه‌جایی Cursor؛ اختلاف‌های پوشش افزوده JSON به‌صورت موردی پذیرفته و مستند شوند؛ تست repeatable با fixture ثابت باشد.
- **پیشنهاد پیاده‌سازی بعدی:** adapter تستی مستقل با ورودی JSON تزریق‌شده، helper نرمال‌سازی خروجی و snapshotهای fixture؛ تست‌ها بدون network/fetch با داده محلی اجرا شوند. سپس به runtime متصل شود.
- **وظیفه ۹ — Fixtureهای ثابت HTML (۱۹ نوامبر ۲۰۲۶):** فایل `alfacode/tests/html-completion-fixtures.mjs` با ۳۲ ورودی ثابت ایجاد شد.
- **وظیفه ۱۰ — Shadow test (۱۹ نوامبر ۲۰۲۶):** فایل `alfacode/tests/html-completion-shadow.test.mjs` ساخته شد. موتور Legacy مرجع mode/context/bounds و close/chain است؛ adapter آزمایشی metadata و enabled/namespace/parentTags و rank/order را از JSON می‌خواند. اجرای GitHub Actions روی commit `f219a887` موفق شد: ۸۸ تست موفق، صفر شکست؛ ۳۲ fixture بررسی و ۱۷ اختلاف رفتاری ثبت شد. اختلاف‌های مهم شامل حذف برخی گزینه‌های Legacy به‌علت parentTags (از جمله div/li در بدنه)، ترتیب rank در head/table/list/select و خالی‌شدن پیشنهادهای SVG زیرعنصر g است. این‌ها موارد بررسی‌اند؛ runtime همچنان Legacy است و هیچ اختلافی خودکار پذیرفته نشده است.
