# نقشه اتصال کاتالوگ‌های HTML، CSS و JavaScript به New page

## هدف
اتصال سه فایل JSON کاتالوگ پیشنهادها به صفحه **New page** در AlfaCode؛ به‌صورت ماژولار، آفلاین، با حفظ رفتار فعلی و امکان توسعه بعدی.

## اولویت‌بندی مراحل

### اولویت ۱ — بررسی معماری و قرارداد داده
- [ ] بررسی New page و مسیر فعلی بارگذاری کاتالوگ/پیشنهادها.
- [ ] بررسی ساختار و schema سه فایل JSON و metadata رکوردها.
- [ ] مشخص‌کردن محل مناسب مصرف داده، بدون افزودن منطق سنگین به فایل هماهنگ‌کننده.
- [ ] تعیین قرارداد API بین New page، ماژول کاتالوگ و موتور پیشنهادها.
- [ ] تعیین راهبرد خطا: اگر یک فایل JSON در دسترس/قابل‌خواندن نبود، سایر زبان‌ها از کار نیفتند.

**معیار پذیرش:** معماری و قرارداد روشن، مسیر فایل‌ها و نقاط اتصال مشخص، بدون تغییر رفتار کاربر.

### اولویت ۲ — طراحی ماژول بارگذاری و مدیریت داده
- [ ] ایجاد یا تکمیل ماژول مستقل loader در ساختار موجود (پس از بررسی، از ایجاد فایل تکراری پرهیز شود).
- [ ] بارگذاری سه فایل مستقل: HTML، CSS، JavaScript.
- [ ] بررسی schema، زبان، نسخه و شکل records هنگام بارگذاری.
- [ ] مدیریت cache و جلوگیری از بارگذاری تکراری.
- [ ] مدیریت خطا و fallback؛ شکست یک کاتالوگ نباید دو کاتالوگ دیگر را مختل کند.
- [ ] اطمینان از مسیرهای محلی و عدم وابستگی شبکه خارجی.

**معیار پذیرش:** loader داده‌ها را معتبر و تفکیک‌شده ارائه دهد؛ خطاها قابل گزارش و ایزوله باشند.

### اولویت ۳ — اتصال به New page
- [ ] اتصال loader به نقطه ورود New page.
- [ ] انتخاب کاتالوگ بر اساس تب/زبان فعال.
- [ ] حفظ مالکیت پیشنهادها توسط زبان مربوط (HTML/CSS/JavaScript) و جلوگیری از پیشنهاد cross-language نامعتبر.
- [ ] جلوگیری از ثبت هم‌زمان چند منبع یا listener تکراری.
- [ ] حفظ عملکرد فعلی پیشنهادها و مسیرهای تایپ/درج.

**معیار پذیرش:** پیشنهادها از JSONهای مستقل تأمین شوند و مسیرهای فعلی خراب یا دوبرابر نشوند.

### اولویت ۴ — Context و صحت پیشنهاد
- [ ] تعریف contextهای پشتیبانی‌شده برای HTML، CSS و JavaScript.
- [ ] اعمال فیلتر context و metadata هر رکورد.
- [ ] کنترل ارتباط property/value در CSS و والد/فرزند و ویژگی‌های HTML.
- [ ] فیلتر موارد browser-only در contextهای غیرمرورگر.
- [ ] مدیریت snippetها به‌صورت کنترل‌شده؛ snippetهای غیرفعال تا فعال‌سازی صریح وارد پیشنهاد عادی نشوند.

**معیار پذیرش:** هر پیشنهاد فقط در context معتبر ظاهر شود.

### اولویت ۵ — درج و تعامل
- [ ] تطبیق متن جستجو با عنوان، نام و کلیدهای رکورد.
- [ ] تفکیک label نمایشی از متن واقعی درج.
- [ ] درج صحیح متن/تگ/property/value/snippet با حفظ متن اطراف.
- [ ] حفظ موقعیت Cursor و selection؛ رفتار placeholder فقط در صورت پشتیبانی.
- [ ] مدیریت Escape، Enter، Tab، Arrow keys و باز/بسته‌شدن فهرست بدون تداخل با editor.
- [ ] جلوگیری از درج تکراری یا تغییر ناخواسته محتوای کاربر.

**معیار پذیرش:** انتخاب پیشنهاد قابل پیش‌بینی باشد و متن موجود، selection یا Cursor ناخواسته تخریب نشود.

### اولویت ۶ — آزمون‌ها و Regression
- [ ] تست loader برای سه فایل، schema، نسخه و زبان.
- [ ] تست خطای بارگذاری هر فایل به‌صورت جداگانه.
- [ ] تست پیشنهادهای نمونه در contextهای معتبر و نامعتبر.
- [ ] تست درج برای HTML، CSS، JavaScript و snippet.
- [ ] تست جلوگیری از cross-language و duplicate suggestions.
- [ ] تست حفظ رفتار فعلی New page و editor.
- [ ] اجرای CI و ثبت نتیجه.

**معیار پذیرش:** آزمون‌های خودکار موفق باشند و regressionهای مسیر New page رفع شوند.

### اولویت ۷ — نسخه آفلاین و کارایی
- [ ] بررسی نحوه جاسازی JSONها در build آفلاین و Manifest.
- [ ] اطمینان از عدم نیاز به fetch خارجی در فایل آفلاین نهایی.
- [ ] کنترل حجم نهایی خروجی.
- [ ] اندازه‌گیری زمان بارگذاری و پاسخ پیشنهادها.
- [ ] آزمون واقعی New page در مرورگر با اینترنت و بدون اینترنت.

**معیار پذیرش:** هر سه کاتالوگ در نسخه آفلاین در دسترس باشند و تجربه تایپ/درج قابل قبول بماند.

### اولویت ۸ — مستندات و تکمیل
- [ ] به‌روزرسانی README ریشه و READMEهای مرتبط.
- [ ] ثبت معماری نهایی و مسیر ماژول‌ها.
- [ ] ثبت تست‌های اجراشده و نتایج واقعی.
- [ ] بررسی و حذف مسیرهای منسوخ یا loaderهای تکراری (فقط پس از تأیید مصرف‌کننده‌ها).
- [ ] بازبینی نهایی و اعلام تکمیل.

## قرارداد منابع داده
- HTML: `alfacode/data/completions.html.json`
- CSS: `alfacode/data/completions.css.json`
- JavaScript: `alfacode/data/completions.javascript.json`

کاتالوگ‌ها منابع مرجع هستند؛ تغییرات داده باید در فایل‌های اصلی انجام شود، نه در خروجی build آفلاین. schema و metadata حفظ شوند.

## اصول پیاده‌سازی
- ماژولار؛ از تجمع منطق در New page یا فایل ریشه جلوگیری شود.
- Offline-first؛ مسیرها محلی و وابستگی بیرونی ممنوع.
- سازگار با رفتار موجود؛ ابتدا audit و تست، سپس اتصال.
- Fail-soft؛ خطای یک زبان مانع کار دو زبان دیگر نشود.
- قابل توسعه؛ افزودن رکورد یا دسته جدید نیازمند تغییرات پراکنده و پرخطر نباشد.
- تست‌پذیر؛ loader، context filtering و insertion تا حد امکان جدا و قابل تست باشند.
- README با هر تغییر کد/ساختار به‌روز شود.

## خارج از محدوده
- افزودن رکوردهای جدید به کاتالوگ‌ها.
- بازطراحی کامل رابط پیشنهادها، مگر اینکه برای اتصال لازم باشد و در مرحله مربوط مستند شود.
- فعال‌سازی خودکار snippetهای غیرفعال بدون بررسی امنیت/رفتار و تأیید.
- تغییر رفتار editor یا New page بدون آزمون regression.
