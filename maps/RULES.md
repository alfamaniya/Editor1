# قوانین و استانداردهای Editor1

## هدف این سند
این سند مرجع قواعد پایدار کار روی مخزن است. جزئیات حوزه‌های تخصصی در سند مربوط نگهداری می‌شود.

## محدوده تغییرات
- ابتدا هدف درخواست را مشخص کن و فقط فایل‌ها/بخش‌های لازم را تغییر بده.
- تغییرات نامرتبط، بازنویسی سلیقه‌ای و پاک‌سازی خارج از درخواست انجام نده.
- فایل‌های فعال را از نسخه‌های آرشیوی `backup/` تفکیک کن؛ آرشیو منبع فعال فرض نشود.
- پوشه `alfacode/src/` فقط با درخواست صریح کاربر تغییر می‌کند.

## کامنت فارسی ابتدای فایل
- فایل‌های قابل کامنت‌گذاری باید در ابتدای فایل توضیح فارسی با نام فایل داشته باشند.
- فرمت توضیح: `#نام فایل: توضیح فارسی` و نشانه کامنت متناسب با زبان انتخاب شود.
- در فایل دارای shebang، خط اجرایی حفظ شود و کامنت توضیحی در خط بعد قرار گیرد.
- JSON و placeholderهایی مانند `.gitkeep` کامنت نمی‌گیرند چون syntax معتبر ندارند.
- کامنت باید کارکرد واقعی فایل را توصیف کند، نه صرفاً نام یا حدس از مسیر.

## README و مستندات
- README در هر تغییر اجرایی پروژه به‌روز شود؛ لینک/خلاصه/درخت مرتبط بررسی شود.
- README نمایه و نقطه شروع است؛ شرح تخصصی در سند حوزه خودش نوشته شود.
- هر صفحه، موتور، ماژول یا workflow جدید در سند دسته مربوط ثبت شود.
- نقشه راه فقط با کار برنامه‌ریزی‌شده یا پیشرفت تأییدشده به‌روزرسانی شود.

## پیگیری تدریجی کامنت‌ها
1. درخواست اصلی کاربر ابتدا انجام شود.
2. در پایان هر درخواست اجرایی، یک فایل بدون تیک انتخاب و محتوای آن بررسی شود.
3. کامنت فارسی خط اول در صورت نیاز اصلاح/تکمیل شود.
4. سپس فقط همان فایل در چک‌لیست درخت README به [x] تغییر کند.
5. فایل‌های مستثنا با [-] مشخص می‌شوند؛ وجود کامنت قدیمی به‌تنهایی کافی نیست.

## تست و گزارش وضعیت
- تست مرتبط اجرا شود، اگر محیط و ابزار در دسترس باشد.
- CI، تست Node، ساخت Offline و بررسی دستی مرورگر از هم جدا گزارش شوند.
- تست اجرا نشده، پاس‌شده اعلام نشود.

## UI و زبان
- زبان رابط کاربر انگلیسی و جهت LTR است.
- فارسی برای توضیحات سورس و مستندات مجاز است، نه متن نمایشی UI مگر درخواست صریح.
- دسترس‌پذیری، تعامل کیبورد و رفتار responsive هنگام تغییر UI بررسی شود.

## CSS و JavaScript
- ظاهر صفحه یا بخش اصلی می‌تواند stylesheet اختصاصی داشته باشد؛ استایل مشترک برای الگوهای مشترک استفاده شود.
- منطق رفتار و اکشن‌ها در JavaScript جدا از markup نگهداری شود.
- از اصلاح selector/rule بدون بررسی تأثیرات مرتبط خودداری شود.
- حفظ declarations نامرتبط و CSS دستی در Visual Editor اهمیت دارد.

## پوشه‌بندی
- فایل‌ها در پوشه مسئولیت خود قرار گیرند؛ از فایل‌های تکراری اجتناب شود.
- `core/` کد فعال UI و runtime است؛ `backup/core-old/` آرشیو است.
- مستندات و نقشه‌ها در `maps/` نگهداری می‌شوند.
